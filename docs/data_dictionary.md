# Experiment Analysis Platform — Data Dictionary

## 1. Overview

This document describes the datasets generated by the Experiment Analysis Platform. The data is synthetic and reproducible using the configured random seed `20261022`.

The six primary datasets are stored in `data/raw/`.

## 2. Experiments — `experiments.csv`

**Purpose:** Stores experiment configuration and lifecycle information.

| Column            | Type    | Description                                        |
| ----------------- | ------- | -------------------------------------------------- |
| `experiment_id`   | String  | Unique experiment identifier.                      |
| `experiment_name` | String  | Human-readable experiment name.                    |
| `hypothesis`      | String  | Hypothesis being tested.                           |
| `primary_metric`  | String  | Primary metric used to evaluate the experiment.    |
| `status`          | String  | Experiment lifecycle status.                       |
| `start_date`      | Date    | Experiment start date.                             |
| `end_date`        | Date    | Experiment end date.                               |
| `random_seed`     | Integer | Seed associated with the experiment configuration. |

**Primary key:** `experiment_id`

## 3. Variants — `variants.csv`

**Purpose:** Defines control and treatment variants for each experiment.

| Column          | Type   | Description                                                |
| --------------- | ------ | ---------------------------------------------------------- |
| `variant_id`    | String | Unique variant identifier.                                 |
| `experiment_id` | String | Experiment to which the variant belongs.                   |
| `variant_name`  | String | Variant name: `Control` or `Treatment`.                    |
| `allocation`    | Float  | Expected fraction of assignments allocated to the variant. |

**Primary key:** `variant_id`
**Foreign key:** `experiment_id` references `experiments.experiment_id`.

**Rule:** Variant allocations for each experiment should sum to 1.

## 4. Audience Members — `audience_members.csv`

**Purpose:** Stores synthetic user attributes and eligibility.

| Column     | Type    | Description                                            |
| ---------- | ------- | ------------------------------------------------------ |
| `user_id`  | String  | Unique synthetic user identifier.                      |
| `age`      | Integer | Synthetic user's age.                                  |
| `country`  | String  | Synthetic user's country.                              |
| `eligible` | Boolean | Indicates whether the user is eligible for assignment. |

**Primary key:** `user_id`

## 5. Assignments — `assignments.csv`

**Purpose:** Records the variant assigned to each user in each experiment.

| Column          | Type      | Description                   |
| --------------- | --------- | ----------------------------- |
| `assignment_id` | String    | Unique assignment identifier. |
| `experiment_id` | String    | Associated experiment.        |
| `user_id`       | String    | Assigned synthetic user.      |
| `variant_id`    | String    | Assigned variant.             |
| `assigned_at`   | Timestamp | Assignment timestamp.         |

**Primary key:** `assignment_id`

**Foreign keys:**

* `experiment_id` references `experiments.experiment_id`.
* `user_id` references `audience_members.user_id`.
* `variant_id` references `variants.variant_id`.

**Rule:** A user should receive only one variant within a given experiment.

## 6. Exposure Events — `exposure_events.csv`

**Purpose:** Records when a user is exposed to an assigned variant.

| Column          | Type      | Description                     |
| --------------- | --------- | ------------------------------- |
| `exposure_id`   | String    | Unique exposure identifier.     |
| `experiment_id` | String    | Associated experiment.          |
| `assignment_id` | String    | Associated assignment.          |
| `user_id`       | String    | User who received the exposure. |
| `variant_id`    | String    | Exposed variant.                |
| `exposed_at`    | Timestamp | Exposure timestamp.             |

**Primary key:** `exposure_id`
**Foreign key:** `assignment_id` references `assignments.assignment_id`.

**Rules:**

* The exposure must reference an existing assignment.
* User, variant, and experiment must match that assignment.
* Exposure must not occur before assignment.

## 7. Conversion Events — `conversion_events.csv`

**Purpose:** Records synthetic conversions and their associated values.

| Column             | Type      | Description                                 |
| ------------------ | --------- | ------------------------------------------- |
| `conversion_id`    | String    | Unique conversion identifier.               |
| `experiment_id`    | String    | Associated experiment.                      |
| `assignment_id`    | String    | Associated assignment.                      |
| `user_id`          | String    | User associated with the conversion.        |
| `variant_id`       | String    | Associated variant.                         |
| `converted_at`     | Timestamp | Conversion timestamp.                       |
| `conversion_value` | Float     | Synthetic monetary value of the conversion. |

**Primary key:** `conversion_id`
**Foreign key:** `assignment_id` references `assignments.assignment_id`.

**Rules:**

* The conversion must reference an existing assignment.
* User, variant, and experiment must match that assignment.
* The conversion must occur within the experiment's date window.
* Conversion values must be numeric and non-negative.
## 8. guardrail_events

**Source:** `data/raw/guardrail_events.csv`

| Column           | Type    | Constraint or purpose                                            |
| ---------------- | ------- | ---------------------------------------------------------------- |
| `experiment_id`  | TEXT    | Associated experiment                                            |
| `variant_name`   | TEXT    | Variant name: `Control` or `Treatment`                           |
| `assigned_users` | INTEGER | Number of assigned users; must be positive                       |
| `payment_errors` | INTEGER | Number of payment errors; must be between 0 and `assigned_users` |
| `refunds`        | INTEGER | Number of refunds; must be between 0 and `assigned_users`        |

**Integrity rules:**

* The experiment must exist.
* Each experiment must have only one record per variant.
* `variant_name` must be `Control` or `Treatment`.
* `assigned_users` must be greater than zero.
* `payment_errors` and `refunds` must be non-negative and cannot exceed `assigned_users`.

**Purpose:**

This dataset supports guardrail analysis by calculating payment error and refund rates for each experiment variant. It helps identify whether a treatment improves the primary metric while negatively affecting important business metrics.


## 9. Entity Relationships

```text
experiments
    |
    +----< variants
    |
    +----< assignments >---- audience_members
                 |
                 +----< exposure_events
                 |
                 +----< conversion_events
```

* An experiment can contain multiple variants.
* An experiment can have multiple assignments.
* A user can participate in multiple experiments.
* Each assignment links one experiment, user, and variant.
* Exposure and conversion events reference assignments.

## 10. Analysis Outputs

| File                           | Description                                         |
| ------------------------------ | --------------------------------------------------- |
| `variant_metrics.csv`          | Conversion metrics by experiment and variant.       |
| `experiment_results.csv`       | Treatment-effect estimates and statistical results. |
| `randomization_results.csv`    | Randomization balance and SRM results.              |
| `guardrail_metrics.csv`        | Guardrail metric summaries.                         |
| `guardrail_results.csv`        | Guardrail decisions.                                |
| `anomaly_detection_report.csv` | Results from anomaly detection.                     |
| `source_manifest.json`         | Dataset metadata and SHA-256 checksums.             |

## 11. Implementation Notes

* All records are synthetic.
* The configured random seed is `20261022`.
* The current full dataset contains 10 experiments, 20 variants, 50,000 eligible users, and 500,000 assignments.
* CSV files are the primary source datasets.
* JSON and SQL-compatible exports are generated from those CSV files.
* The current SQLite export contains the six source tables, but database-level relational constraints are not yet explicitly enforced.
* Guardrail data is currently generated inside the analysis workflow rather than stored as a separate source-event dataset.

Update this document whenever the implemented data schemas or business rules change.
