# Experiment Analysis Platform

A reproducible, data-driven platform for designing experiments, validating randomization, estimating treatment effects, evaluating guardrail metrics, and detecting data-quality anomalies.

## 1. Project Overview

Online experiments, including A/B tests, help teams evaluate whether a product or feature change improves business outcomes. However, unreliable randomization, invalid event data, and regressions in critical metrics can lead to incorrect decisions.

This project implements a synthetic experimentation workflow that generates experiment data, validates its integrity, checks randomization balance, estimates treatment effects, evaluates guardrail metrics, and presents results through a dashboard.

**Important:** All datasets and outcomes generated by this project are synthetic. They do not represent actual users or real business performance.

## 2. Objectives

* Generate reproducible synthetic experiment datasets.
* Support multiple experiments and control/treatment variants.
* Assign eligible users to experiment variants.
* Generate exposure and conversion events.
* Validate primary keys, foreign keys, eligibility, timestamps, and business rules.
* Detect sample-ratio mismatch (SRM).
* Estimate conversion rates and treatment effects.
* Calculate confidence intervals and statistical significance.
* Evaluate guardrail metrics and flag potential regressions.
* Detect selected data-quality anomalies.
* Export data in CSV, JSON, and SQL-compatible formats.
* Preserve dataset checksums and source metadata.
* Present results through a Streamlit dashboard.

## 9. Analysis Methodology

### Randomization validation

The platform compares observed variant assignment counts against expected counts derived from configured allocations. A chi-square goodness-of-fit test is used to identify potential sample-ratio mismatch.

The implemented detector uses a configured significance threshold. Passing this check does not prove that every aspect of randomization is correct.

### Treatment effect estimation

The platform calculates control and treatment conversion rates, absolute effect, relative effect, confidence intervals, and p-values.

The primary analysis follows an intention-to-treat approach: assigned users are analyzed according to their assigned variant rather than requiring an exposure event.

The current implementation uses a normal-approximation method for the conversion-rate difference. Statistical assumptions and multiple-comparison considerations should be reviewed before applying the approach to real experiments.

### Guardrail evaluation

Guardrail metrics track potential negative effects that may outweigh a primary-metric improvement.

The current synthetic workflow evaluates payment-error and refund rates. Configured thresholds determine whether an experiment passes or fails the guardrail checks.

### Anomaly detection

The project includes synthetic anomaly cases for selected scenarios, including:

* Multiple variant assignments
* Exposure before assignment
* Conversion outside the permitted window
* Metric-definition changes

These cases support testing of the anomaly-detection implementation. The currently tested scenarios do not imply that every possible anomaly is detected.

## 10. Data Exports and Traceability

Generated CSV datasets are stored in `data/raw/`.

The export module produces JSON datasets under `outputs/json/`, a SQLite database at `outputs/experiment_analysis.db`, and SQL seed statements at `outputs/seed.sql`.

The source manifest at `outputs/source_manifest.json` records dataset names, relative paths, column names, record counts, file sizes, generation configuration, and SHA-256 checksums.

The SQLite export contains six source tables with explicit primary keys, foreign keys, uniqueness constraints, and applicable check constraints. Database integrity and foreign-key checks passed against the current generated dataset. Some cross-table business rules, including event-to-assignment consistency and experiment allocation totals, are validated by the application rather than enforced entirely by SQLite.

## 12. Limitations and Future Improvements

Potential improvements include:

* Add database-level enforcement for additional cross-table business rules.
* Add explicit MetricDefinition and GuardrailMetric source entities to the relational model.
* Move guardrail event generation into a dedicated, traceable data-generation stage.
* Validate all event-window and experiment-lifecycle rules.
* Improve anomaly detection coverage and automated negative tests.
* Account for multiple hypothesis testing when analyzing several experiments.
* Add richer experiment configuration and metric-definition records.
* Extend reproducibility checks to analysis outputs and exported artifacts.
* Improve error reporting, structured logs, and test coverage.

## 13. Responsible Use

This is a synthetic-data demonstration project for experimentation analysis. Its generated metrics should not be interpreted as real product performance, and its statistical implementation should be independently reviewed before use in production decision-making.
